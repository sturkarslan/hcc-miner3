## Open questions

- **[2026-09-29] Cross-cohort survival comparability (approved by user; horizon implemented in step 03).** CLCA follow-up ends at ~4 years (assumed cutoff) versus 10 in TCGA, and CLCA survival is better. Checks done:
  - **The cutoff assumption barely matters up to 3 years.** 95% of CLCA operations were in 2018 (range 2017-12 to 2020-06), so every patient has at least ~2 years of real follow-up before any cutoff. Moving the cutoff from 2020-06-30 to 2021-09-30 changes KM OS at 12/24/36 months by ≤ 0.01 (0.94/0.86/0.80–0.81) and RFS by ≤ 0.03 (0.71/0.62–0.63/0.57–0.60).
  - Deaths are recorded steadily through 2021 Q3 (4.3–10.8 per 100 person-years each year), so follow-up was active. Recurrences fall from 29–38 to 7–11 per 100 person-years after year 2, which matches the known early-recurrence peak after resection, not loss of follow-up. The 2020 dip could partly be COVID-related.
  - **CLCA's better survival is not explained by stage.** CLCA BCLC: C 283, B 162, A 36, 0 13 (57% BCLC C; 57% with MVI M1/M2). TCGA AJCC: I 173, II 87, III 85, IV 6. KM at 12/24/36 months: OS CLCA 0.94/0.86/0.81 vs TCGA 0.83/0.71/0.63; RFS/PFS CLCA 0.70/0.63/0.57 vs TCGA 0.64/0.48/0.39. Likely contributors: different populations and care (HBV, antiviral therapy, surgical selection), TCGA OS includes non-cancer and perioperative deaths, and **22% of CLCA patients have unknown status and are dropped** (bias if missingness is informative). Can't separate these with the data we have.
  - **Proposed handling:** (1) never pool raw survival times across cohorts: KM within cohort, Cox stratified by cohort, MINER GuanRank computed within cohort; (2) truncate every cohort at a common 36-month horizon for any cross-cohort or validation analysis (cutoff-insensitive for CLCA; keep full-length TCGA as a sensitivity analysis); (3) train the risk model in TCGA and evaluate in CLCA and LIRI-JP by within-cohort discrimination (C-index, time-dependent AUC at 12/24/36 months, HR high vs low with risk groups defined within each cohort), never by absolute survival; (4) regulon/program Cox per cohort, combined by fixed-effect meta-analysis, requiring consistent direction; (5) adjust for stage within cohort (BCLC for CLCA, AJCC for TCGA); (6) primary endpoint early recurrence/progression (CLCA RFS, TCGA PFS), OS secondary (only 33 deaths among CLCA expression samples).
  - Worth asking the CLCA authors: the true last-follow-up dates, and why 110 patients have unknown survival status.

- **[2026-09-29] Pulled cloud commit 9f6293a (step 04b module QC).** Reviewed; `regulonDf.csv` columns (`Regulon_ID`, `Regulator`, `Gene`) verified against the GBM output. - **[2026-09-29] Coexpr result and the 909-gene module: no parameter change yet; check it with step 04b first.** `miner3-coexpr` (ComBat, bulk defaults): 12,316 of 13,120 genes in 765 modules, median 12 genes, largest 909.
  - How MINER builds big modules (isb_miner3 1.2.4 source): `cluster()` takes the genes at the 5% tails of correlation with each of 10 PCs, per iteration, then splits them. `reviseInitialClusters()` then merges any modules whose first principal axes correlate > 0.925, repeated up to 5 times. That merge produces large modules. The threshold is hard-coded; the CLI doesn't expose it.
  - `miner3-mechinf` re-runs the same clustering (same random_state), so it sees the same 909-gene module. It does not split modules by regulator: for each module it tests the TFs whose expression correlates |r| ≥ `-mc` with the module's first axis for target enrichment (hypergeometric p < 0.05, uncorrected). The regulon is TF targets ∩ module, and `getRegulons` then merges each TF's sets across modules. A 909-gene module can therefore produce many overlapping regulons that all follow one signal, and they then tend to collapse into one program in `miner3-subtypes`.
  - **When it matters:** it's fine if the module is one strong biological axis (e.g. immune infiltration: coherent, PC1-dominated). It's a problem if it is (a) several signals merged (weak PC1, strong PC2, many genes loosely attached) or (b) technical (tracks cohort or sample-quality stats).
  - **New `scripts/04b_module_qc.py`** reports this per module. It covers coherence (PC1/PC2 share, gene–eigengene r), cohort and label η², within-cohort correlation with sample stats, marker programs (T cell, B/plasma, myeloid, stromal, endothelial, interferon, proliferation, hepatocyte, CTNNB1) and ribosomal/mito/histone content. After mechinf, it also reports regulon count and redundancy per module (pairwise Jaccard and regulon-eigengene r). Figures m1–m3.
  - **Decision rule:**
    - PC1 ≥ ~0.3, few genes with r < 0.3, one clear marker program, cohort η² ≈ 0 → keep.
    - Merged or technical → first try `-mc 0.3` for mechinf; the MINER library default in `axisTfs` is 0.3, the CLI default 0.2. This cuts the TFs tested against broad axes.
    - If that isn't enough, drive the library directly with a stricter merge threshold (e.g. 0.95) as a sensitivity run.
    - Compare the resulting regulons/programs with the default run rather than replacing it.

## Environment / tooling

- **[2026-09-29] MINER3 preprocessing, verified in `miner.py`.** `preprocess()` = `remove_null_rows` → `correct_batch_effects()` → ID conversion.
  - `correct_batch_effects()` z-scores each gene across all samples. Only when `--skip_tpm` is absent **and** the SD of per-sample means is ≥ 0.15 does it call `preProcessTPM()`.
  - `preProcessTPM()`: keep genes non-zero in ≥ 50% of samples → scale each sample so its positive-value median = 1023 → log2(x+1) → quantile-normalize samples, then genes → gene z-score (clipped below −4).
  - **No TMM, no ComBat, no cohort term.** This is a median-scaling + quantile normalization, so it cannot remove cohort effects when cohorts differ in gene-specific ways (platform, pipeline, gene annotation).
  - `zscore()` returns the input unchanged if the mean of positive values is < 0.1, so pre-z-scored input passes through untouched.
- **[2026-09-29] MINER3 risk prediction.**
  - `miner3-riskpredict` CLI takes a JSON spec (`exp`, `idmap`, `coexpression_dictionary`, `coexpression_modules`, `regulon_modules`, `mechanistic_output`, `regulon_df`, `overexpressed_members`, `underexpressed_members`, `eigengenes`, `filtered_causal_results`, `transcriptional_programs`, `transcriptional_states`, `primary_survival_data`, optional `translocations`). It runs GuanRank on KM estimates + Cox per regulon and per program, KM plots, and activity heatmaps. It needs causal-inference output first.
  - `miner3-survival` is similar and takes a network dir + survival CSV (first two columns: duration, observed) + translocation CSV.
  - The full risk classifier (`generatePredictor`, `riskStratification`, `iAUC`, `predictRisk`; xgboost or decision tree, 20% high-risk cutoff) is in the library, not the CLI. It's used in the paper notebooks (`external/miner3_mattwall/miner/src/MINER_Figure_5.ipynb`). **`xgboost` is not installed in the `miner3` env.**
